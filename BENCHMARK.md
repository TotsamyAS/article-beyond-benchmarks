# Детерминированный бенчмарк

Отдельный LLM-only эксперимент: [`baseline_llm.ipynb`](baseline_llm.ipynb),
инструкции — [`LLM_BENCHMARK.md`](LLM_BENCHMARK.md). Его результаты сохраняются
в `baseline_results/llm/`, а результаты ниже — в `baseline_results/determined/`.

Запуск: выполнить ячейки `baseline_determined.ipynb` по порядку. По умолчанию
ноутбук запускает **оригинальный fast-renderer PriceTracker**, встроенный в сам ipynb:

- `original_fast` — оригинальное извлечение всех товаров страницы;
- `original_fast_query` — те же товары после штатного фильтра релевантности запросу.

Встроены неизменённые TypeScript-модули `extractor`, `candidates`, `utils`, `profiles`,
`blockDetection`, `queryRelevance`, `contracts`, а также исполняемый JS вместе с точными
версиями npm-зависимостей и их лицензиями. Сохраняется исходная логика DOM/CSS,
JSON-LD, встроенного JSON, профилей сайтов, выбора полей и лимит 500 товаров.
Исходная папка `D:\Job_Codes\PriceTracker` и установка npm-пакетов **не нужны**.
При запуске ноутбук проверяет SHA256 и создаёт служебную `.benchmark_runtime/` из
своего содержимого. Удаление этой папки не удаляет парсер: она будет восстановлена.

Нужен Node.js; эталонный прогон выполнен с **Node.js 24.6.0 и Python 3.13.13**.
Для воспроизводимого окружения используйте `config/requirements-benchmark.lock.txt`;
основные Python-пакеты также зафиксированы в первой ячейке. Во время извлечения
сеть, браузер и LLM не используются. Селекторы из работающей БД приложения не загружаются.

Исторические B1/B2/B3 оставлены как необязательные контрольные методы; они запускаются
только при явном добавлении в `VARIANTS`. B2 — упрощённый CSS-парсер, его показатели
не следует выдавать за показатели оригинала. Предыдущие результаты архивированы
в `.artifacts/notebook-original/*-legacy-results.zip`.

Результаты сохраняются в `baseline_results/determined/`. Для обновления synthetic v2
по умолчанию выбраны `RUN_DATASETS = ("synthetic", "robustness")`. `RUN_DATASETS = None`
запускает все три набора: `synthetic`, `robustness`, `industrial`.
Чтобы воспроизвести industrial-строки эталонного `original_comparison.xlsx`, задайте:

```python
RUN_DATASETS = ("industrial",)
VARIANTS = ("original_fast", "original_fast_query")
RESUME_EXTRACTION = False
```

Затем выполните **Restart Kernel → Run All**. Ячейки определений выполняются все,
но извлечение запускается только для выбранных наборов. Сохранённые результаты
industrial включаются в общие CSV после проверки настроек и контрольных сумм
GT, HTML и файлов результатов. Их файлы не перезаписываются. Источники общих таблиц
записываются в `baseline_combined_manifest.json`; устаревшие результаты исключаются
из общих таблиц с явным сообщением. После изменения логики извлечения или оценки
выберите все затронутые наборы для нового запуска: проверка сохранённых данных
не доказывает эквивалентность произвольных изменений кода.

`RESUME_EXTRACTION=True` позволяет продолжить прерванное извлечение только при
совпадении HTML, URL, запроса, исходного парсера и версии Node.js. Для повторно
использованных страниц время не подставляется заново. Обработка двух режимов
использует общее извлечение: не суммируйте его время между режимами. По умолчанию
выполняется свежий прогон.

## Корпус и разметка

`synthetic` содержит 20 исходных страниц / 420 товаров (12–30 на страницу); `robustness` — 200
модифицированных страниц / 4 200 товаров. Версия: `synthetic-v2-12to30`. Их HTML находятся в общей папке
`synthetic/html`, но состав каждого набора задаёт собственный `*_pages.csv`,
сопутствующий `*_ground_truth.csv`. В результатах сохраняются `base_page_id`,
`base_entity_id`, тип мутации и исходный шаблон для парных сравнений. Групповые
метрики включают тип мутации, шаблон и номер варианта.

Версия v2 создана 2026-10-03. Генератор `scripts/generate_synthetic_dataset.py`
воспроизводит HTML и GT из зафиксированных входов `config/synthetic_seed/`.
Без аргументов он проверяет точное совпадение файлов; `--write` пересоздаёт их.
Первые 100 товаров сохранили свои метки и ID. При сопоставлении разных версий
учитывайте `dataset_version`: размеры страниц изменились. В аналитические CSV
попадают `gt_meta__dataset_version`, `gt_meta__product_origin` и
`page_meta__n_entities` для анализа качества по числу товаров на странице.

2026-10-01 исправлена перепутанная раскладка файлов synthetic: 200 модифицированных
HTML восстановлены по исходным SHA256 генератора, 20 исходных — по canonical page ID.
Таблица robustness GT сохранена побайтно; clean GT восстановлен из согласованных
исходных меток тех же товаров. Предсказания бенчмарка при восстановлении не использовались.
Исторический скрипт `scripts/repair_synthetic_dataset.py` применим только к v1;
`--write` создаёт ZIP исходных файлов и выполняет восстановление. Отчёт и резервная
копия первого восстановления находятся в `.artifacts/synthetic-repair-20261001T124041913010Z/`.

Для `industrial/dind.xlsx` список файлов задаёт лист `Pages`. Дополнительные
файлы, в том числе примеры карточек, не включаются. Отсутствующий HTML остаётся
в manifest с `skip_reason=missing_html` и исключается из метрик. Относительный
путь сохраняется целиком: одинаковые имена в разных папках не смешиваются.

`www.example.com` и `example.com` считаются одним доменом. У URL удаляются
параметры, фрагмент и завершающий слеш; сохраняется прежнее приведение к нижнему
регистру. Остальные поддомены и протоколы не объединяются.

Политика `ANNOTATION_POLICY="labeled"` учитывает заполненные `in_progress`
текущего проверенного пользователем GT. Режим `"done"` требует статуса
`done/reviewed/complete/completed`. Явные `pending/todo/new/unannotated`
не оцениваются даже при заполненных полях. Частично размеченная страница
исключается целиком; `skip/excluded` исключает всю страницу. Пустая страница
размечается строкой `is_product=0`.

Оценка среза ограничивает **и GT, и предсказания** переданным manifest.
Дубликаты идентификаторов товаров и нормализованных ключей GT вызывают явную
ошибку, чтобы результат нельзя было неоднозначно присоединить к разметке.

## Цена

`gt_price_state` имеет три состояния:

| Состояние | Смысл | Оценка |
|---|---|---|
| `present` | Известна числовая цена | Сравнение с допуском ±1% |
| `absent` | Подтверждено отсутствие цены | Предсказанная цена — `price_FP` |
| `unannotated` | Цена не размечена | Поле цены не оценивается |

Для industrial ноль в GT означает `absent`. Для пустой ячейки отсутствие
должно быть подтверждено колонкой `gt_price_state`/`price_state_gt`/`price_state`,
флагом `price_absence_confirmed` или уже записанной пометкой
`USER_REVIEW: no price`. Остальные пустые цены остаются `unannotated`.
В synthetic ноль является обычной числовой ценой.

Товар с отсутствующей ценой участвует в оценке извлечения сущности и названия.
`price_presence_ok` проверяет наличие/отсутствие цены у совпавших товаров;
пропущенному товару эта проверка не начисляет правильное отсутствие цены.
`unexpected_price_FP` отдельно считает цены, извлечённые при GT `absent`.

## Результаты и присоединение классификации

Файлы находятся в `baseline_results/determined/<dataset>/`:

- `baseline_review.xlsx`: Excel для ручной проверки. Лист `Сравнение` содержит одну
  строку на GT-товар: эталонное название/цену и значения каждого метода рядом.
  Есть фильтры, закреплённые заголовки, идентификаторы датасета, подсветка ошибок.
  Лист `Лишние` сохраняет предсказания без пары в GT, `Все_результаты` — подробные
  результаты, `Страницы` — в том числе пустые и исключённые страницы.
  `Метрики` дополнительно показывает долю правильных названий среди товаров с
  совпавшим URL (`name_accuracy_on_matched`); это условная оценка, не замена F1.
- `baseline_predictions.csv`: результаты всех методов, включая пропуски и
  лишние предсказания; идентификаторы GT, состояние цены и счётчики TP/FP/FN.
- `baseline_page_results.csv`: все страницы manifest для каждого метода,
  включая пустые, неразмеченные и отсутствующие. Для исключённых страниц
  `is_scored=False`; их счётчики нельзя трактовать как успешную оценку.
- `baseline_metrics.csv`: метрики сущностей, названий и цен.
- `baseline_entity_analytics.csv`: расширенная таблица результатов с исходными
  полями GT (`gt_meta__*`), метаданными Pages (`page_meta__*`) и manifest
  (`manifest__*`). Включает все классы, кластеры, наличие, рейтинг и другие
  дополнительные поля, которые есть в исходном Excel.
- `baseline_group_metrics.csv`: сводки по сайту, запросу, региону/маршруту,
  типу страницы и имеющимся классам/кластерам. Для каждой группы сохранены
  объём выборки, TP/FP/FN, micro P/R/F1; для групп страниц также macro F1
  и матрица ошибок определения наличия товаров.
- `baseline_error_breakdown.csv`: категории ошибок по методам и сайтам.
- `baseline_error_distributions.csv`: интервальные распределения сходства
  названий и относительных ошибок цены, готовые для гистограмм.
- `baseline_extraction_log.csv`: статус каждого метода на каждой странице,
  время чтения/разбора HTML и извлечения, число кандидатов до/после удаления
  дубликатов, достижение лимита, тип/текст/трассировка исключений.
- `baseline_analysis_profile.json`: описание цен GT с квантилями, состав
  выборки, статистика времени, размеры/колонки таблиц и определения показателей.
- `groundtruth_loaded.csv`: GT с исходными дополнительными колонками, например
  классом или кластером, и нормализованными полями оценки.
- `html_manifest.csv`, `baseline_raw_predictions.csv`: состав корпуса и сырые результаты.
- `original_parser_responses.jsonl`: полные ответы встроенного оригинального парсера
  по каждой доступной странице, включая статус blocked/empty, диагностику и query filter.
- `groundtruth_audit.json`, `benchmark_run.json`: полнота разметки, настройки,
  идентификатор запуска и контрольные суммы, SHA256 исходного/исполняемого парсера,
  версии зависимостей, Python и Node.js, число повторно использованных страниц.

Ключ для классификации товаров — `(dataset, entity_id)`, для страниц —
`(dataset, page_id)`. В результате один товар имеет одну строку **на метод и
запуск**. Для объединения запусков добавляется `benchmark_run_id`; `run_id`
по-прежнему описывает исходный сбор страницы.

`match_status` явно различает `matched_gt`, `missing_prediction`,
`unmatched_prediction`. Для пропущенного товара сохраняются `entity_id` и
`gt_id`; `pred_id` пуст. Для лишнего предсказания GT-идентификаторы пусты,
но есть `pred_id` и `page_id`. `result_id` есть у любой строки результата.
Пустым страницам товарные entity_id не выдумываются.

`name_similarity` сохраняет числовое сходство названий, а поля
`price_error_signed/absolute/relative/relative_absolute` — отклонение цены.
Относительные ошибки записаны долями: `0.25` означает 25%. Для GT-цены 0
относительная ошибка не определена. Диагностики считаются только для пар с
двумя сравнимыми значениями, поэтому MAE/MAPE не заменяют общие P/R/F1 с
учётом пропущенных и лишних товаров.

В таблице страниц есть `page_TP/FP/FN/TN`: правильно ли определено наличие
хотя бы одного товара. Это отдельная задача от качества извлечённых полей.
Показатели страниц позволяют делать парные сравнения методов,
распределения качества и bootstrap по страницам. Macro F1 усредняется по всем
оцениваемым страницам группы; при нулевом знаменателе F1 страницы принимается
равным 0. Счётчики разных `error_labels` могут пересекаться.

Время записано в миллисекундах. Чтение и разбор HTML общие для методов и
повторяются в строках журнала: не суммируйте их повторно между вариантами.
`extract_ms` измеряется отдельно для каждого метода. Для повторно используемых
предсказаний журнал содержит `not_recorded` и пустое время, а не выдуманные нули.
Ошибки выполнения отмечаются отдельно от успешного извлечения нуля товаров.

Пример присоединения дополнительных столбцов из Excel:

```python
pred = pd.read_csv("baseline_results/determined/industrial/baseline_predictions.csv")
labels = pd.read_excel("industrial/dind.xlsx", sheet_name="GroundTruth")
labels = labels.loc[labels.entity_id.notna(), ["entity_id", "class_label", "cluster_id"]]
labels["dataset"] = "industrial"
joined = pred.merge(labels, on=["dataset", "entity_id"], how="left", validate="many_to_one")
```

`class_label` и `cluster_id` здесь — пример будущих колонок. Внутри одного
метода/запуска GT-ключ проверяется как `one_to_one`; между несколькими методами
нормально иметь несколько результатов на одну строку разметки.

Для групповых метрик суммируйте `entity_TP/FP/FN`, `name_TP/FP/FN`,
`price_TP/FP/FN`, затем пересчитывайте P/R/F1. Лишние предсказания без класса
GT нельзя молча выбрасывать: сохраняйте отдельную группу или используйте
классификацию страниц. Усреднять F1 отдельных страниц вместо пересчёта нельзя.

## Аудит и проверка изменений

Excel создаётся автоматически самим ноутбуком после каждого прогона. Общий файл:
`baseline_results/determined/baseline_review_all.xlsx`. Чтобы сформировать только
Excel по уже сохранённым CSV, без нового извлечения:

```powershell
.\.venv\Scripts\python.exe scripts/export_benchmark_review.py
```

Проверка совпадения результатов ноутбука с эталонным Excel, без нового извлечения:

```powershell
.\.venv\Scripts\python.exe scripts/verify_original_baseline.py
```

Проверяются GT и исходники по SHA256, обе строки метрик, все идентификаторы/названия/цены
и прочие поля результатов (кроме нового benchmark_run_id). Если исходный JSONL прогона
доступен рядом с эталонным Excel, сравниваются и полные ответы всех 239 страниц.
Итог — `baseline_results/determined/original_parity.json`. Скрипт не подключается
к исходному репозиторию. Для оценки всех GT-товаров используйте `original_fast`;
query-фильтрация — отдельная политика отбора и может снижать полноту относительно GT.

Сохранённый эталон находится в `baseline_results/validation/original/`:
`original_comparison.xlsx` сравнивает B1/B2 и оригинал с GT;
`original_pages.jsonl` содержит исходные ответы и диагностику;
`original_source.json` — контрольные суммы оригинального кода и входных данных.
Старый `scripts/validate_original_mechanism.py` был использован для создания этого эталона
из внешнего репозитория; он больше не является основным способом запуска baseline.
Выборочная диагностика `core_field_probe.csv` проверяет Python-выбор полей на
тех же B2-фрагментах; специально выбранные ошибки не являются оценкой всего корпуса.

`ready_for_available_pages` проверяет доступную область оценки.
`paper_ready_closed_world` дополнительно требует наличия всех перечисленных
HTML и отсутствия размеченных страниц вне manifest. `FAIL_ON_INCOMPLETE_GT=True`
останавливает запуск при нарушении второго условия.

Регрессионные проверки: `python -m unittest discover -s tests -t . -v`.
Они выполняют код самого ноутбука, включая основную ячейку на маленьких наборах.

На 2026-10-01 проверены 239 доступных industrial-страниц и 6 317 товаров.
В Pages остаётся отсутствующий `html/hahn-kolb.ru-run-8238baa5.html`; он явно
отмечен и не участвует в метриках. Исходный `industrial/dind.xlsx` при этих проверках не менялся.
Исторические результаты B1/B2 сохранены в архиве перед переходом на оригинальный
парсер. Происхождение текущих результатов записано в `benchmark_run.json` каждого
набора и в `baseline_combined_manifest.json` общей таблицы.
