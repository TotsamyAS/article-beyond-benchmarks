# LLM-only baseline

Основной файл — `baseline_llm.ipynb`. Он содержит полный код запуска, оценки и
экспорта: сопутствующие Python-файлы при выполнении notebook не требуются.
CLI `scripts/run_llm_benchmark.py` исполняет определения именно из этого notebook.

Модель зафиксирована: **`qwen/qwen3.8-omni-flash`**, провайдер **RouterAI**.
Ключ читается из переменной `ROUTERAI_API_KEY` окружения или `.env` в корне проекта.
Ключ и HTTP-заголовок Authorization не сохраняются в артефактах и не печатаются.
Веб-сайты товаров не посещаются; используются существующие снимки HTML.

## Запуск

Используется то же Python-окружение, что и для determined. Дополнительный SDK не нужен.
Для воспроизведения окружения предусмотрен `config/requirements-benchmark.lock.txt`.

Из корня проекта, PowerShell:

```powershell
# Офлайн-проверка входов и приблизительного объёма; без ключа и без API.
.\.venv\Scripts\python.exe -X utf8 scripts/run_llm_benchmark.py --plan

# Полный платный прогон synthetic + robustness + industrial.
.\.venv\Scripts\python.exe -X utf8 scripts/run_llm_benchmark.py --run
```

Повтор той же команды продолжает эксперимент: завершённые страницы не отправляются
повторно. Независимое повторение — новый `--experiment`, например `qwen38-repeat-2`.

Небольшой реальный тест API перед большим прогоном можно выполнить отдельно:

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/run_llm_benchmark.py --run --datasets synthetic --limit 2 --experiment qwen38-smoke
```

Это отдельная выборка и папка; её метрики не смешиваются с полным экспериментом.
Тесты кода используют имитацию API, поэтому не подтверждают доступность платного
endpoint для конкретного ключа, баланс или фактическое соблюдение параметров провайдером.

В Jupyter: открыть `baseline_llm.ipynb`, в конфигурации сменить `RUN_MODE="plan"`
на `RUN_MODE="run"`, выполнить **Restart Kernel → Run All**.
Для одного набора задать `RUN_DATASETS=("industrial",)` или CLI `--datasets industrial`.
Общие отчёты содержат наборы, выбранные текущей командой; чтобы собрать все три,
повторить полную команду — завершённые страницы будут прочитаны с диска.

Офлайн-пересборка отчётов без API:

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/run_llm_benchmark.py --replay
```

## Протокол P_llm

Следует определению §4.3 черновика: один полный HTML в одном контексте, восемь полей
`name`, `price`, `old_price`, `product_url`, `image_url`, `availability`,
`delivery_time`, `reviews_count`. `availability` — boolean или null.
HTML передаётся целиком после UTF-8-декодирования с replacement для ошибочных байтов.
Сохраняются scripts, JSON-LD и встроенное состояние; нет очистки DOM, выделения
карточек, чанкинга, предварительного отсеивания пустых/заблокированных страниц,
детерминированного fallback или дополнительных запросов для исправления JSON.
GroundTruth не попадает в промпт и не участвует в выборе ответа.

Заданы temperature=0, top_p=1, JSON-object response format,
reasoning={effort: none, exclude: true}, timeout=180 секунд.
Максимум выходных токенов — **65 536**; это явная настройка данного эксперимента,
в черновике лимит для LLM-only не определён. Лимита количества карточек нет.
Выбранная модель и эти параметры не подменяются автоматически после ошибок.
Наличие `exclude=true` само по себе не доказывает отключение reasoning:
фактические reasoning tokens сохраняются из usage, если провайдер их сообщает.

HTML сверх контекста не обрезается. Отказ API из-за длины контекста, обрезанный
ответ (`finish_reason=length`), невалидный JSON или несоответствие схеме
регистрируются как ошибки. Некорректный JSON не восстанавливается эвристиками.
При частично невалидном массиве сохраняются валидные записи и отдельный список
отклонённых строк. Ошибки остаются в знаменателе оценки на размеченных страницах.

Распознавание по скриншотам не включено в этот baseline: §4.3 определяет P_llm
через полный HTML. Возможность модели принимать изображения нужна для будущего
гибридного режима. Полный production L9 с БД/семантическими валидаторами здесь
не запускается: используется общий проверенный контракт оценки существующего benchmark.

## Возобновление и ошибки

В пределах EXPERIMENT_ID фиксируются код/настройки, GT, список страниц, HTML,
URL, запрос и промпт. Изменение входов или протокола требует нового имени
эксперимента. При повторном запуске проверяются сигнатуры запросов и контрольные
суммы ответов. Одновременный запуск одного эксперимента в двух процессах запрещён
блокировкой ОС; при завершении процесса блокировка снимается автоматически.

До HTTP-вызова сохраняются полный запрос и отметка начала. Сразу после ответа
сохраняется полный сырой ответ, затем итог страницы. Если процесс оборвался после
сохранения ответа, он будет восстановлен без обращения к модели.

Для транспортных ошибок, 408/429 и некоторых 5xx предусмотрено до трёх попыток
с задержкой; все попытки и их стоимость учитываются, включая неуспешные.
401/402/403/404 останавливают прогон, чтобы не повторять проблему доступа/баланса
на всём корпусе. Исправив причину, ранее ошибочные страницы можно повторить явно:

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/run_llm_benchmark.py --run --retry-errors
```

Обычное возобновление повторно использует также завершённые ответы с ошибками,
что сохраняет наблюдённый исход и не расходует деньги автоматически.
Если процесс был убит во время отправленного запроса и ответа нет на диске,
его результат и возможное списание неизвестны. Для явного повтора такого запроса:

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/run_llm_benchmark.py --run --retry-uncertain
```

Повторы отмечаются в журнале. После осознанных повторов ошибок итоговые метрики
относятся к последнему исходу страницы; стоимость включает всю историю попыток.
Для независимой статистической репликации используйте новый EXPERIMENT_ID.

## Результаты

Папка по умолчанию: `baseline_results/llm/qwen38-omni-flash-v1/`.
План сохраняется в `plan/`, не создавая фиктивных предсказаний или метрик.

- `experiment.json`: зафиксированный протокол и снимок каталога/цен модели.
- `run_status.json`: состояние запуска, выбранные и завершённые наборы.
- `baseline_review_all.xlsx`: LLM и GT по всем выбранным наборам.
- **`baseline_comparison.xlsx`**: GT, original_fast, original_fast_query и LLM рядом.
  Original-результаты добавляются только при совпадении GT, HTML и проверке файлов.
- `comparison_provenance.json`: какие original-результаты вошли и почему другие исключены.
- Общие `baseline_*_all.csv`: стандартные метрики, страницы, сырые и сопоставленные товары.
- `paper_required_metrics_all.csv`: дополнительные строгие метрики для обеих архитектур,
  macro-F1 по name/price/product_url, PSR⁺/PSR⁰ и bootstrap-интервалы.
- `paper_robustness_deltas.csv`: разности strict macro-F1 synthetic–industrial и synthetic–robustness.

В `<dataset>/` также сохраняются стандартные CSV, `baseline_review.xlsx`,
аналитика по доменам/запросам/классам/мутациям, ошибки и метаданные GT/Pages.
Дополнительно:

- `llm_calls/<page-hash>/request.json.gz`: полный запрос, включая HTML, без ключа;
- `attempt-*.started.json`, `attempt-*.response.json.gz`, `result.json`: история вызовов,
  сырые HTTP-ответы, финальный результат и контрольные суммы;
- `llm_attempts.csv`: по строке на попытку, модель/провайдер ответа, usage, токены,
  reasoning/cache, HTTP-код, finish reason, время и оценка стоимости;
- `llm_page_responses.json`: результаты всех обработанных страниц;
- `llm_rejected_rows.csv`: записи, отклонённые проверкой схемы/URL;
- `llm_cost_summary.json`: известные суммы, количество неизвестных значений,
  среднее и p95 числа попыток/стоимости, статусы, новые и повторно использованные вызовы;
- `paper_entity_results.csv`, `paper_page_results.csv`: подробности строгой оценки;
- `paper_optional_results.csv`, `paper_optional_metrics.csv`: сравнение дополнительных
  полей и **покрытие разметкой**. Пустые GT-ячейки не считаются подтверждённым отсутствием.

Сырые восемь полей есть в `baseline_raw_predictions.csv`, полные оригинальные
значения — в ответах API. Связь результатов с датасетом: `(dataset, entity_id)`
для GT-товара, `(dataset, page_id)` для страницы; у лишних предсказаний нет GT ID.
`result_id`/`pred_id` относятся к конкретному методу. Дополнительные классы и кластеры
из GT и Pages сохраняются в `baseline_entity_analytics.csv`.

Денежные оценки выражены в RUB по снимку RouterAI `/models`, снятому в начале
эксперимента. Это не банковское списание: учитывайте тарифы, кеш и неизвестный
usage. `usage.cost` сохраняется отдельно вместе с валютой, если API её сообщает;
неизвестная валюта не объявляется USD или RUB. Пропущенные токены/стоимость не
подменяются нулём. Время — диагностика текущей машины и сети, а не контролируемый
latency-бенчмарк. Интервалы качества — 1000 bootstrap-перевыборок страниц, seed 42;
это не парный тест значимости и не оценка вариативности повторных LLM-запусков.

## Что нужно согласовать в тексте статьи

Черновик прочитан из DOCX `Articles/[draft] Beyond Synthetic Benchmarks_ ...`.
Он содержит предварительные утверждения, которые не следует переносить в результаты:

| В черновике | Реальный протокол/корпус |
|---|---|
| Qwen3.6 через OpenRouter | Qwen3.8 Omni Flash через RouterAI, по выбору автора |
| 15 / 150 / 250 страниц | 20 / 200 / 240 записей manifest; industrial доступно 239 HTML |
| Synthetic parser F1=100% | Для оригинала получено другое значение; использовать фактические CSV |
| Все восемь полей полностью размечены | GT не содержит полного покрытия; optional coverage выводится отдельно |
| Price exact match | Основные метрики сохраняют ±1% для сопоставимости; strict-таблицы используют точное число |
| Полная production-валидация L9 | В offline benchmark общий URL/GT-контракт, без БД и semantic validation |
| Только товары, релевантные запросу | Текущая GT размечает товары страницы; LLM извлекает все, query — метаданные |

Строгие supplementary-метрики используют ту же URL-идентичность, что и baseline:
все query-параметры удаляются, www игнорируется. Это шире удаления только tracking
параметров в черновике. Для буквального воспроизведения другой политики URL или
query-relevance потребуется единое изменение разметки/оценки для всех методов.
Правило пользователя «industrial цена 0 означает отсутствие цены» сохранено.

## Проверка и сопровождение

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -t . -p test_llm_benchmark.py -v
```

Код разрабатывается в `scripts/llm_baseline_*.py`, затем **встраивается** в ipynb
командой `python scripts/build_llm_notebook.py`. Builder обновляет кодовые хеши и
очищает outputs. Тесты исполняют встроенный код. Shared GT/evaluation definitions
берутся из determined notebook, а не импортируются из отдельного runtime-модуля.

Документация API: [RouterAI quickstart](https://routerai.ru/docs/guides/overview/quickstart),
[параметры](https://routerai.ru/docs/guides/overview/parameters),
[каталог моделей](https://routerai.ru/api/v1/models).
