# Предварительное заполнение GroundTruth

Скрипт `../scripts/prefill_industrial_gt.py` читает только локальные HTML, перечисленные
на листе `Pages` файла `dind.xlsx`. Примеры из `html/cadr_examples` служат
образцами вёрстки и не добавляются в набор страниц.

Из корня проекта:

```powershell
python scripts/prefill_industrial_gt.py          # проверка и JSON-отчёт, без записи Excel
python scripts/prefill_industrial_gt.py --write  # резервная копия и заполнение Excel
python scripts/prefill_industrial_gt.py --metadata-only --write  # только восстановление query
python -m unittest test_prefill_industrial_gt -v
```

Зависимости перечислены в `../config/requirements.txt`.

## Что появляется в Excel

- По одной строке на уникальную пару «HTML-страница, URL товара».
- `name_gt`, `price_gt`, `product_url_gt`, `is_product = 1`.
- Наличие, рейтинг и срок доставки — только когда для них есть извлекаемые
  данные. Регион не подставляется из региона поискового запроса.
- `annotation_status = in_progress`, `annotator = auto:card-prefill`.
- В `notes` — способ извлечения и условия цены; в комментариях новых GT-ячеек —
  HTML-файл, селектор или путь JSON и исходное значение цены.
- Лист `GT_Prefill_Audit` с результатами по всем страницам. Полные кандидаты,
  пропуски и конфликты находятся в `gt_prefill_report.json`.

Это заготовки для ручной проверки. После проверки исправьте значения и поставьте
`annotation_status = done`. Текущий `baseline_determined.ipynb` учитывает также
заполненные строки `in_progress`; перед итоговой оценкой завершите их проверку.

## Правила извлечения

Для доменов используются конкретные селекторы карточек. У Lemanapro читается
`window.INITIAL_STATE["plp"].plp.plp.products.productsData`, ограниченный списком
`productsIds`; JavaScript не выполняется. В имеющихся снимках Petrovich карточки
уже присутствуют в DOM, используются `data-test` атрибуты.

Учитывается текущая цена, а не зачёркнутая. OfficeMag: цена одной единицы из
данных карточки, условия оптовых ступеней требуют проверки. Цены с WB Кошельком
и Яндекс Пэй отмечаются в `notes`. У Komus отмечается минимальный заказ.
Товарные рекламные баннеры OfficeMag тоже извлекаются, с отдельной пометкой.
Товары не фильтруются по поисковому запросу: извлекаются карточки, присутствующие
на странице, включая рекомендации и витрины главной страницы.

Пропущенная цена остаётся пустой. Нулевая цена в метаданных при надписи «по
запросу» также остаётся пустой. Ссылки становятся абсолютными, параметры запроса
и фрагменты удаляются в соответствии с ключом сопоставления в ноутбуке.

В проверенном industrial пользовательская запись `price_gt = 0` означает
**отсутствие цены**, а не бесплатный товар. Скрипт сохраняет такой ноль и не
заполняет его заново. Ноутбук при запуске industrial преобразует нули во
внутренние пропуски с `gt_price_state=absent`; сам Excel и режим synthetic не
меняются. Подтверждённое отсутствие цены не мешает аудиту полноты. Если метод
извлёк цену у такого товара, она учитывается как `price_FP`. Неизвестная,
неподтверждённая цена имеет состояние `unannotated` и не оценивается.
Схема результатов и присоединение классификации описаны в `../BENCHMARK.md`.

## Поисковые запросы и результаты ручной проверки

Пустые `query` дополняются на листах `Pages` и `GroundTruth`, в том числе у
проверенных строк `done`. Источники по приоритету: `page_url`, `source_url`,
canonical/og:url в HTML, заполненное поле поиска и однозначные ссылки пагинации
того же сайта. Рекламные ссылки не используются. Поддерживаются `q`, `text`, `query`, `search`, `searchtext`,
`keyword`: кириллица декодируется, `+` между словами становится пробелом,
последнее непустое повторяющееся значение берётся из URL. При нескольких разных
запросах в HTML-ссылках значение остаётся неопределённым. У M.Video после
редиректа без параметров запрос дополнительно читается из заголовка страницы
поиска. Уже заполненные query не перезаписываются.

Источник query сохраняется в комментарии ячейки, колонке `query_source` листа
`GT_Prefill_Audit` и JSON-отчёте. Для `--metadata-only` создаётся отдельный
`gt_metadata_report.json`; извлечение товаров в этом режиме не запускается.

После явного подтверждения человеком доступны флаги:

```powershell
python scripts/prefill_industrial_gt.py --metadata-only --confirm-empty-pending --confirm-unpriced-unavailable --write
```

`--confirm-empty-pending` устанавливает `is_product = 0`, `annotation_status = done`
только у пустых строк `pending`. `--confirm-unpriced-unavailable` устанавливает
`in_stock_gt = 0` у товаров с пустой/нулевой ценой. Цена сохраняется без изменений,
в `notes` фиксируется подтверждение пользователя. Эти флаги отражают результат
ручной проверки текущего набора, их нельзя применять автоматически к новому
непроверенному набору.

Отсутствие найденных карточек не превращает страницу в отрицательный пример:
исходная строка остаётся `pending`. Отсутствующий HTML отмечается `missing_html`.
Такие страницы нужно проверить отдельно.

## Повторный запуск и резервная копия

Заполненные ячейки сохраняются. Скрипт дополняет только пропуски, сопоставляя
существующие строки по странице и URL. Страницы со статусом `done`/`skip` или
явной отрицательной разметкой не дополняются. Повторный запуск с теми же HTML
не создаёт дубликаты. После изменения правил уже заполненные значения также
сохраняются — исправляйте их вручную или восстанавливайте исходную копию.

Перед изменением Excel рядом создаётся `dind.before-prefill-<дата-время>.xlsx`.
Новый файл сначала сохраняется и проверяется отдельно, затем заменяет оригинал.
Другие исходные листы и `dind_summary.json` сохраняют информацию первоначальной
сборки набора; результаты автозаполнения записываются в отдельный аудит.
